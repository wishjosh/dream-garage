## 현재 게임

차고에서 차량을 고르고 경주를 완주하면 순위에 따라 상금을 받습니다. 상금으로 도색·휠·엔진·타이어·브레이크를 구매하고 다음 경주에 도전합니다. 가속·브레이크·후진은 각각 별도 버튼이며 드리프트는 선택해서 사용합니다. 차 뒤 시점과 운전석 시점을 지원합니다.

Tavaculo 운전석에는 별도 공간 시안에서 확인한 Gallardo 원본 실내를 적용했습니다. 낮은 왼쪽 눈 위치와 원본 앞유리·A필러·대시보드·핸들의 비율을 유지하며, 실제 주행 물리에서 계산한 조향에 따라 원본 핸들이 돌아갑니다. 시선은 같은 방향으로 최대 6° 따라갔다가 정면으로 돌아옵니다. 차고나 일시정지 메뉴에서 **조향 따라 시선 이동**을 끌 수 있으며, 이 선택은 현재 열린 탭에서만 유지됩니다. 상금·꾸미기 기록의 저장 형식은 바꾸지 않았습니다.

원본 계기판 앞에는 실제 속도와 전후진 상태를 보여 주는 작은 화면을 더했습니다. 화면은 최대 초당 10회 갱신하며 단수와 엔진 회전수는 속도에 맞춘 게임용 표시입니다. 룸미러는 뒤쪽 도시와 차량을 실제로 비춥니다. 세로 화면에서는 실내를 변형하지 않고 같은 후방 영상을 화면 위쪽에 따로 표시합니다. 가로에서는 실내 계기, 세로에서는 보조 속도 표시로 주행 상태를 확인합니다. F2002는 기존의 중앙 운전석을 유지합니다. 원본 실내의 공간감을 도시 주행에 연결한 구성이며 실차 치수·엔진·변속기의 정밀 재현을 뜻하지 않습니다.

스마트폰은 가로 화면을 권장합니다. 왼손으로 좌우 방향을, 오른손으로 가속·제동·후진·드리프트를 조작합니다. 컴퓨터는 방향키/WASD, Space(제동), X(후진), Shift(드리프트), C(시점), P/Esc(일시정지), R(도로 복귀)를 사용합니다.

## 자료와 수치에 근거한 주행 검증

2026-10-22 사용자가 맡긴 VPP·PhysX 기준의 점검·동일 조건 시험·반복 개선을 비교 시안에 적용했습니다. [개선 후 주행](https://wishjosh.github.io/dream-garage/handling-study.html?v=handling-6), [수정 전 주행](https://wishjosh.github.io/dream-garage/handling-study.html?v=handling-6&model=before), [그래프와 전체 결과](https://wishjosh.github.io/dream-garage/handling-results.html?v=audit-1)를 공개합니다. 이 수치 검증 단계에서는 비교 시안을 다뤘으며, 이후 본 경주 적용은 위 항목에 정리했습니다.

### 근거와 단순화의 범위

- [VPP Tires](https://vehiclephysics.com/blocks/tires/)의 하중×마찰계수 한계와 점진적 미끄러짐을 검토했습니다. VPP 곡선의 가로축은 접촉면 속도 차이(m/s)이며 이 모델의 옆 미끄럼각(rad)과 다릅니다. VPP 기본 곡선의 수치를 그대로 가져오지 않았습니다.
- [PhysX 5.6.1 Vehicles](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/docs/Vehicles.html)의 합성 힘 제한, 저속 불안정성과 작은 시간 간격을 검토했습니다. 이 코드는 PhysX의 sticky constraint나 SDK를 구현·실행한 것이 아닙니다.
- 현재 타이어는 각도에 비례하는 옆 힘과 구동·제동 요구를 부드럽게 합산하는 근사입니다. 실제 종방향 슬립·바퀴 회전 관성·4륜 하중 이동·서스펜션·하중에 따른 타이어 강성 변화는 모델링하지 않습니다. 기존 구동 접지 보정 최대 18%는 게임용 값으로 유지했습니다. 운전 보조나 실차 보정으로 검증했다고 보지 않습니다.

### 발견한 오류와 수정 근거

기존 모델은 속도를 최소 2.5m/s로 놓고 계산한 옆 속도 각도에서 조향각을 뺐습니다. 실제 속도가 더 낮아도 조향각이 그대로 힘을 만들어 저속 회전을 과장했습니다. 앞바퀴 좌표의 실제 접촉 속도를 먼저 계산하도록 수정했습니다. 그 상태에서도 남아 있던 속도 비례 접지 약화와 임의 회전 감쇠가 회전을 지나치게 억제해 제거했습니다. 정지 안정성은 접촉 속도 정규화와 최대 1/240초 계산으로 확보했습니다. 앞바퀴 제동은 바퀴 방향 속도를 거스르게 했고, 차체 회전에 따른 속도 좌표 변환은 에너지를 추가하지 않는 정확한 회전으로 바꿨습니다.

### 시험의 재현과 판정 기준

npm run benchmark:handling으로 [결과 JSON](dist/handling-results.json)을 다시 생성하고 npm test로 확인합니다. [시험 본체](dist/handling-bench.mjs)의 고정 입력은 두 모델이 공유합니다. 수정 전은 커밋 25afbf5803310ccea54584f55138d86ff93a6452의 [그대로 보존한 모델](dist/handling-baseline.mjs), 두 중간 단계는 tests/fixtures/에 있습니다. 결과에는 소스 해시(LF 줄바꿈 기준), 조건, 30Hz 시계열과 단계별 판정을 포함합니다. 보고서의 다시 계산 버튼은 별도 작업 스레드에서 같은 함수를 실행합니다.

속도 고정 시험은 시험 장치가 앞 속도 U를 강제합니다. 벽·경로 추종·자동 반대 조향은 없습니다. 기준은 평면 두 축의 정상 회전 운동식 r = Uδ/(L+K U²), K = m/L×(b/Cf−a/Cr)입니다. 앞뒤 힘의 합 mUr와 회전 모멘트 균형 aFf=bFr에서 도출했습니다. 작은 조향·낮은 횡가속에서만 비교하며 5%는 근사식의 허용 오차로 정했습니다. 자유 주행 시험에 속도 고정을 사용하지 않습니다.

회복은 양쪽 방향·20/60/100km/h·브레이크 0/40/100%의 18조건에서 동일한 옆 속도 2.5m/s·회전 속도 0.5rad/s로 시작합니다. 미끄럼각 1°·옆 속도 0.2m/s·회전 속도 0.05rad/s 미만을 0.5초 유지한 구간의 시작을 회복 시점으로 셉니다. 3초 이내는 이 게임의 목표입니다. 수정 전에도 회복 조건은 통과했으며 최종안의 60km/h·40% 제동 회복은 약 0.733초입니다.

제동은 5/40/60/100km/h에서 0.1m/s 아래를 정지로 정의합니다. 60km/h 정지 시간은 2.325→2.183초, 거리는 약 17.98→17.93m입니다. 더 짧을수록 무조건 좋다는 판정은 하지 않고, 접지·항력으로 가능한 최대 감속을 넘지 않는지 확인합니다. 구동 없는 1,200개 속도·옆 속도·회전·조향·제동 조합에서 운동 에너지 증가가 없어야 합니다. 합성 타이어 힘은 하중×마찰계수 이하, 좌우 주행은 대칭, 30/60/120 표시 속도의 결과는 같아야 합니다.

자동 118개와 로컬 모바일 화면 56조합(6크기×2조향, 20회복, 24제동·조향)이 통과했습니다. 보고서 3개 화면 폭의 넘침·버튼 크기, 6개 그래프와 브라우저 재계산을 확인했습니다. 실제 모바일 하드웨어·발열·장시간 성능·호진이의 운전감은 아직 검증하지 않았습니다. 수치 통과를 실차 재현이나 재미의 검증으로 확대하지 않습니다.
